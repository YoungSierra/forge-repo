# Unity Test Framework scaffold (consumer projects)

**Unity MCP** for creating asmdef and asset refresh; **Unity CLI** (`unity test`) for running Test Runner — see `V57/docs/mcp/UNITY_MCP_REQUIREMENT.md` and `UNITY_CLI_INTEGRATIONS.md`. **Do not** run tests via Test Runner MCP when `run_unity_test_runner_via_cli: true`.

Canonical layout for EditMode / PlayMode tests generated by `/spec implementa`. Without assembly definitions under `Assets/_Game/Tests/`, test `.cs` files compile into `Assembly-CSharp` and `[UnityTest]` fails with **CS0246**.

This document is **project-agnostic**. Names come from your game’s **assembly prefix**, not from a fixed title like Coin Rush.

---

## Assembly prefix (`{Prefix}`)

All paths and assembly names use a single PascalCase token `{Prefix}` (no spaces).

| Source (priority) | Example |
|-------------------|---------|
| 1. `implementation.testScaffold.assemblyPrefix` in the spec YAML | `SpaceRoguelike` |
| 2. `CONTEXT.md` → Project Identity → `test_assembly_prefix` | `MyGame` |
| 3. Derived from `project_name` (fallback only) | `My Cool Game` → `MyCoolGame` |

**Recommendation:** set `test_assembly_prefix` explicitly in `CONTEXT.md` so asmdef names match your root namespace (e.g. `MyGame`).

### Deriving from `project_name` (fallback)

When `test_assembly_prefix` is omitted:

1. Split `project_name` on whitespace and punctuation.
2. PascalCase each non-empty segment.
3. Concatenate (e.g. `My Cool Game` → `MyCoolGame`).

If the result is ambiguous, set `test_assembly_prefix` in `CONTEXT.md`.

## Required package

`Packages/manifest.json` must include:

```json
"com.unity.test-framework": "1.6.0"
```

Use a 1.x version compatible with your Unity Editor.

## Required folders and asmdef files

Let `{Prefix}` be resolved as above.

| Role | File path | `"name"` in asmdef |
|------|-----------|-------------------|
| EditMode tests | `Assets/_Game/Tests/EditMode/{Prefix}.Tests.EditMode.asmdef` | `{Prefix}.Tests.EditMode` |
| PlayMode tests | `Assets/_Game/Tests/PlayMode/{Prefix}.Tests.PlayMode.asmdef` | `{Prefix}.Tests.PlayMode` |

Both test asmdef files must use the modern Test Framework layout (Unity 2022.3 LTS+):

```json
{
  "name": "{Prefix}.Tests.EditMode",
  "references": ["UnityEngine.TestRunner", "UnityEditor.TestRunner", "{Prefix}"],
  "includePlatforms": ["Editor"],
  "precompiledReferences": ["nunit.framework.dll"],
  "defineConstraints": ["UNITY_INCLUDE_TESTS"]
}
```

PlayMode asmdef: same `references`/`defineConstraints`, omit `includePlatforms` (or set per your platform targets).

The **`references`** entry points at the **runtime** game assembly (see below). Test assemblies do not auto-reference `Assembly-CSharp` in current Unity versions — without this, tests fail with CS0234 (`{Prefix}.Features` not found).

Optional but recommended: `"rootNamespace": "{Prefix}.Tests.EditMode"` (or `.PlayMode`).

### Runtime game assembly (required for tests)

| Role | File path | `"name"` in asmdef |
|------|-----------|-------------------|
| Game / runtime code | `Assets/_Game/Scripts/{Prefix}.asmdef` | `{Prefix}` |

Place at `Assets/_Game/Scripts/` so all gameplay scripts under `Assets/_Game/Scripts/**` compile into `{Prefix}` instead of `Assembly-CSharp`. Add package references your scripts need (e.g. `"Unity.InputSystem"`).

Example `Assets/_Game/Scripts/MyGame.asmdef`:

```json
{
    "name": "MyGame",
    "references": ["Unity.InputSystem"]
}
```

| Role | Path | Assembly name |
|------|------|----------------|
| EditMode | `Assets/_Game/Tests/EditMode/MyGame.Tests.EditMode.asmdef` | `MyGame.Tests.EditMode` |
| PlayMode | `Assets/_Game/Tests/PlayMode/MyGame.Tests.PlayMode.asmdef` | `MyGame.Tests.PlayMode` |

## Test class layout

Place test classes under subfolders (any depth below the asmdef folder):

- `Assets/_Game/Tests/EditMode/Features/.../*Tests.cs`
- `Assets/_Game/Tests/PlayMode/Features/.../*Tests.cs`

Namespaces should align with `{Prefix}.Tests.EditMode` / `{Prefix}.Tests.PlayMode` (see existing tests in the repo).

Spec YAML often lists **logical** paths without `Assets/`:

- `Tests/EditMode/...` → `Assets/_Game/Tests/EditMode/...`
- `Tests/PlayMode/...` → `Assets/_Game/Tests/PlayMode/...`

## `implementation.testScaffold` in specs

```yaml
implementation:
  testScaffold:
    package: com.unity.test-framework
    assemblyPrefix: null   # null → use CONTEXT.md; set to override per spec
    testAssembliesReference: TestAssemblies
```

The agent resolves full asmdef paths from `{Prefix}`; you do not need to duplicate paths in every feature spec unless you use a non-standard layout.

---

## Agent behavior (SDD pack)

1. **Resolve `{Prefix}`** from spec → `CONTEXT.md` → `project_name` (see priority table).
2. **Validate spec** — If `implementation.tests` is non-empty, run the test scaffold checklist (`unity-spec-skill.md`). FAIL → report missing package/asmdef with resolved paths.
3. **Implement** — **EnsureTestScaffold**: create missing asmdef for `{Prefix}` (idempotent; do not overwrite custom asmdef without `--force`).
4. **Bootstrap** — In consumer projects (`Assets/` present), run **EnsureTestScaffold** even without `--with-tests`.

---

## Manual verification

`Window → General → Test Runner` → Edit Mode / Play Mode.

After recompile, you should see assemblies `{Prefix}.Tests.EditMode` and `{Prefix}.Tests.PlayMode` (not tests inside `Assembly-CSharp`).

---

## Importing this pack into a new game

1. Copy the **`V57/`** folder next to `Assets/` at the Unity project root.
2. Create or sync `CONTEXT.md` with `test_assembly_prefix: YourGame`.
3. Run `/spec --bootstrap` (creates asmdef if missing) or let the first `/spec implementa` with tests run **EnsureTestScaffold**.
4. Use `--no-tests` only if you intentionally skip the Test Framework gates.
